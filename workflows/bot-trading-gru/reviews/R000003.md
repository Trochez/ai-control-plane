A separate manual recovery invocation was then required to create and validate the missing artifacts before the run could be completed and published.

The test also exposed two orchestration defects independent of the model response: `spawn-opencode` still attempts an interactive tmux attach in `run` mode, producing `open terminal failed: not a terminal`, and `complete-run` does not advance `last_completed_run_id`, leaving it at `R000002` after R000003 completion.

## Rationale

The target-repository acceptance criteria were ultimately satisfied, but the principal P000003 acceptance objective — a fully unattended Planner -> watcher -> OpenCode -> evidence -> completion -> publication cycle — required manual intervention. Therefore the framework is not yet ready to be declared unattended-GO.

## Required Remediation

1. Make `spawn-opencode` non-interactive in `OPENCODE_MODE=run` and never attach a terminal in that mode.
2. Make `run-opencode-session` contract-aware: a process exit code of 0 must not be treated as success when mandatory evidence is missing or invalid. Add bounded automatic recovery/retry within the same run.
3. Make `complete-run` set `last_completed_run_id` to the completed run.
4. Make `handoff-to-planner` idempotent when the Planner has already advanced the workflow to `PLAN_READY`.
5. Preserve the explicit `omniroute/openrouter/openrouter/free` model configuration.
6. Validate the remediations before the next unattended smoke test.
